# Operator Panel v0.6.0 Release Notes

**Release date:** 2026-09-23

The Storyboard editor: video drafts move out of one JSON textarea and into a
scene editor with reordering, per-scene regeneration and an approval trail.

## Drafts live in `data/panel/storyboards/`

**Plan draft** calls the same `POST /v1/content/video-plan` the Video Studio
uses (Storyboard Agent, then Video Director Agent) and stores the answer as one
JSON file: the brief, the storyboard, the render timeline, the approval trail
and the last render job. The store normalizes every scene against the
renderer contract before writing, so a draft that the panel shows is a draft
Media Studio can render. Writing is one atomic replace at mode `600`.

## The scene editor

The Storyboard view lists drafts (title, status, scenes, seconds, aspect) and
opens the selected one in a scene list. Each scene carries duration,
narration, visual, emotion, asset type, transition and animation:

- **Up**/**Down** reorder, **Remove** drops, **Add scene** appends; each of
  these saves immediately, so the operator never loses an edit to a reload.
- **Regenerate** calls `POST /v1/content/scene` on the Smart Router (0.6.3)
  with an optional instruction and replaces that scene only.
- **Validate** posts the assembled document to `POST /timeline/validate` on
  Media Studio, the same check the Video Studio uses.
- **Approve**/**Reject** set the status and append a note to the trail;
  **Render** submits the timeline to the `timeline-video` driver and follows
  the job (queued/running -> `rendering`, done -> `rendered`, failed ->
  `failed`). The draft card shows the job id and the trail keeps every change.

A rejected draft cannot be rendered, and a draft that is already rendering
cannot be queued twice; both are rejected with a message instead of a second
job. Drafts are listed newest first, and a corrupt file is skipped rather than
hiding the rest of the list.

## Endpoints

```text
GET    /api/video/storyboards
POST   /api/video/storyboards
GET    /api/video/storyboards/<id>
PUT    /api/video/storyboards/<id>
DELETE /api/video/storyboards/<id>
POST   /api/video/storyboards/<id>/approve
POST   /api/video/storyboards/<id>/reject
POST   /api/video/storyboards/<id>/render
POST   /api/video/storyboards/<id>/scenes/<n>/regenerate
```

Every write endpoint requires the panel CSRF header, as the rest of the
console does. The Smart Router is required for planning and regeneration
(`SMART_ROUTER_ADMIN_API_KEY`), Media Studio for validation and rendering.

## The panel documents itself

A new **Docs** view carries the complete built-in manual: one card per panel
view (Overview through Actions) explaining what it shows and how to use it,
followed by the full `/api/` reference — session and CSRF rules, status and
inventory reads, the video/storyboard endpoints, configuration, environment
and platform writers, the Hermes/orchestration/knowledge proxies, the
NotebookLM session endpoints, the whitelisted actions, a complete curl login
and write example, and the error contract. The reference is generated from
the same endpoint list the console itself calls, and the base URL in the
examples is the origin the operator is already using.
