# Operator Panel v0.5.1 Release Notes

**Release date:** 2026-09-23

Two corrections that came out of running the video pipeline on a live stack,
plus the bind matrix in the Overview.

## The worker is the authority on its drivers

Video Studio read `MEDIA_STUDIO_DRIVERS` from `.env` and told the operator a
driver was missing while the worker was, in fact, able to run it (or the other
way around, when `.env` was updated but the container had not been recreated).
The view now asks `GET /session/info` on the Media Studio service and reports
the drivers the running worker loaded; `.env` is only the fallback for an
unreachable worker. The warning names the source it read:

```text
The timeline-video driver is not enabled (read from the running worker);
add it to MEDIA_STUDIO_DRIVERS in .env and recreate the media-studio container.
```

## Network exposure reflects what is actually published

The Overview listed a warning for every host bind in `.env`, including profiles
that were not running at all (a stopped `omniroute` looked exposed). The
exposure block now:

- reads compose state and marks each bind with the container state,
- warns only for services that are up: a stopped container exposes nothing,
  and a profile that is switched off is reported as `not running` (`docker
  compose ps` lists the enabled profiles only, so an absent service is evidence
  that nothing is published),
- keeps the warning when Docker cannot be reached, because the setting still
  needs review,
- prints the host ports next to the bind address,
- covers the `hermes` service as well (`HERMES_BIND_IP`),
- keeps the dedicated n8n/MCP and RustFS notes, and folds every other
  published service into one summary line instead of one warning each
  (`These services are published beyond loopback: nine-router:20128
  (192.168.4.222), open-webui:3000 (192.168.4.222), ...`),
- renders a **Network exposure** table (service, key, bind, state, host ports)
  in the Overview so the operator sees the whole matrix without reading `.env`.

## Upgrade

```bash
cd /path/to/content-manager
./manage.sh pull          # or: docker compose pull panel
./manage.sh start
```

The image is `afsharidevops/content-panel:0.5.1`; the GitHub workflow builds
and pushes it, so the server never builds locally.
