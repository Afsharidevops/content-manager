# Operator Panel v0.5.0 Release Notes

**Release date:** 2026-09-22

The console becomes the Content Operations Center: the same session now plans
and renders videos, shows the Hermes control plane, tracks orchestrator runs,
and tests knowledge retrieval.

## Video Studio

A new `Video Studio` view drives the Phase 2 pipeline from the browser:

- plan a video with the Smart Router content agents (topic or script, aspect
  ratio, language, seconds, brand label) and get a storyboard plus a timeline;
- edit the timeline JSON in place, validate it against the renderer's own
  normalizer, then submit it to the Media Studio `timeline-video` driver;
- watch the render queue with per-job status, log tail, cancel, retry, artifact
  download and inline `<video>` preview.

The render queue retries a failed job with the exact driver, prompt and params
the worker recorded, so a retry reproduces the same render.

## Hermes control center

`Hermes` shows the router version, mode and policy, the measured request,
cost, latency and error-rate numbers for the last 24 hours, the registered
agents, the four seeded content production agents, routing profiles, tier
selection, and the top models by request count. Deep links open the router's
own Operations Center and Flight Deck consoles.

## Orchestration center

`Orchestration` lists recent multi-agent runs with status, approval mode, step
progress, reviewer verdict and the step that is waiting for approval, and shows
one run's steps, outputs and errors in full.

## Knowledge center

`Knowledge` lists the knowledge bases with chunk counts, indexes new
documents (chunked and embedded by the router), and runs retrieval tests: pick
bases, ask a question, and read the scored matches.

## API

```text
GET    /api/video/studio                  render jobs, driver list, router readiness
POST   /api/video/plan                    storyboard + timeline from the router agents
POST   /api/video/timeline/validate       renderer-schema validation of a timeline
POST   /api/video/render                  submit an edited timeline to Media Studio
GET    /api/video/jobs/<id>               one render job with its log tail
DELETE /api/video/jobs/<id>               cancel a queued render
POST   /api/video/jobs/<id>/retry         resubmit a job with the recorded params
GET    /api/video/artifacts/<job>/<name>  stream one artifact through the panel session
GET    /api/hermes/overview               control-plane agents, models and telemetry
GET    /api/orchestration/runs            recent orchestrator runs
GET    /api/orchestration/runs/<id>       one run with its steps
GET    /api/knowledge                     knowledge bases and chunk counts
POST   /api/knowledge/documents           index one document into a base
POST   /api/knowledge/search              retrieval test
```

Every write route keeps the existing panel rules: session cookie plus the
`X-Panel-Csrf` header, and nothing reaches the browser without operator
authentication. Artifacts stream through the panel, so the Media Studio port
stays on loopback.

## Configuration

The panel reads the stack `.env`, so no new container variables are required.
The views report a missing `SMART_ROUTER_ADMIN_API_KEY`,
`SMART_ROUTER_INTERNAL_URL`, `MEDIA_STUDIO_INTERNAL_URL` or a
`timeline-video` driver that is not listed in `MEDIA_STUDIO_DRIVERS` as a
warning banner instead of failing silently.

| Variable | Default | Meaning |
| --- | --- | --- |
| `SMART_ROUTER_INTERNAL_URL` | `http://smart-router:8080` | Router address on the stack network |
| `SMART_ROUTER_ADMIN_API_KEY` | - | Key the panel uses for router admin reads |
| `SMART_ROUTER_CLIENT_API_KEY` | - | Fallback key when no admin key is set |
| `SMART_ROUTER_CONSOLE_URL` | `http://$SMART_ROUTER_BIND_IP:$SMART_ROUTER_PORT` | Console link shown in the Hermes view |
| `MEDIA_STUDIO_BRAND_LABEL` | - | Brand label applied to a planned timeline |

## Upgrade

```bash
cd /path/to/content-manager
./manage.sh pull          # or: docker compose pull panel
./manage.sh start
```

The image is `afsharidevops/content-panel:0.5.0`; the GitHub workflow builds
and pushes it, so the server never builds locally.
