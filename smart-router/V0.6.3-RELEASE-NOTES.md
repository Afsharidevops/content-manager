# Hermes Smart Router v0.6.3 Release Notes

**Release date:** 2026-09-23

One additive endpoint for the operator's storyboard scene editor.

## `POST /v1/content/scene` regenerates a single scene

The Storyboard Agent produces a whole storyboard, which is the right shape for
planning and the wrong one for revising: an operator who wants a shorter second
scene should not receive a redrawn storyboard where the other scenes changed
too. The new endpoint takes the draft context and returns exactly one scene:

```json
{
  "topic": "Running Docker containers on MikroTik RouterOS",
  "index": 2,
  "instruction": "make it shorter and mention the container store",
  "storyboard": {"scenes": ["..."]},
  "language": "fa"
}
```

The answer is parsed and repaired with the same bounds as a storyboard scene
(`normalize_scene`): durations clamped to 2-20 seconds, transitions and
animations restricted to the documented enums, the first scene forced to
`cut`, and an answer with neither narration nor a visual rejected as
`scene_invalid`. The endpoint uses the Storyboard Agent prompt plus the
operator instruction; no new agent is registered, so the control database and
the panel agent catalog are unchanged.

The panel's Storyboard view calls this endpoint from its per-scene
**Regenerate** button and replaces only that scene in the stored draft.

## Virtual keys can be deleted permanently

`DELETE /control/api/keys/{id}` used to be a soft revoke. The key now accepts
the same permanent-delete contract as groups and agents:

```text
DELETE /control/api/keys/{id}                        revoke (reversible)
DELETE /control/api/keys/{id}?purge=true             delete the row
DELETE /control/api/keys/{id}?purge=true&cascade=true
                                                     delete ACL/budget references too
```

A purge that still has references answers `409 key_in_use` with the ACL rule
and budget ids in `error.details`, so nothing disappears unnoticed. Access ->
Users & Keys shows an **Active** column and a **Delete** button next to
**Revoke**; the confirmation walks through the cascade when references exist.

## The Docs page is now the operator and API manual

Docs was a short orientation page. It is now the complete built-in reference:
one section per navigation area (Observe, Build, Tools, Routing, Access,
System), the sign-in and first-run checklists, upgrade and backup commands, an
API guide with base URLs and authentication, the OpenAI-compatible and
Anthropic-compatible endpoint lists with curl samples, the content production
endpoints, the Operations Center API map, the virtual key lifecycle, and
ready-to-copy client configurations for **Codex** (`~/.codex/config.toml`) and
**Claude Code** (`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`).

The page content lives in `smart_router/panel_docs.py` and is injected into
the panel at build time, so the guide ships with the image it documents.

## Upgrade

```bash
sed -i 's/^SMART_ROUTER_IMAGE_TAG=.*/SMART_ROUTER_IMAGE_TAG=0.6.3/' .env
docker compose --profile smart-router pull smart-router
docker compose --profile smart-router up -d smart-router
```
