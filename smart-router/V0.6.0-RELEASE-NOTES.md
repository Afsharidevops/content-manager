# Hermes Smart Router v0.6.0 Release Notes

**Release date:** 2026-09-14

## Multi-agent Orchestrator

- New Operations Center **Orchestrator** page with the matching
  `/api/orchestrations` API: plan preview, create-and-run, list, detail, delete,
  and the per-run `execute`, `approve`, and `reject` transitions.
- The planner pass produces a validated machine-readable plan
  (`goal`, `steps[]` with `title`, `agent`, `action`, `tools`,
  `approval_required`, `max_attempts`). A step that references an unknown or
  disabled agent is rejected with HTTP 422 instead of being silently dropped,
  and a planner answer that is not machine-readable degrades to a deterministic
  single-step plan with a note.
- Sequential execution runs every pending step through the existing agent path,
  carries earlier step output forward, and retries a failed step once by default
  (three attempts maximum) before the run is marked `failed`.
- Approval gating pauses the run in `awaiting_approval` before a sensitive step.
  Approval resumes the run from that step; rejection marks the step `rejected`
  and skips the remaining steps.
- A reviewer pass after the last step records `success`, `failure`, or
  `uncertain` plus findings and an optional rollback suggestion.
- The planner receives the recent completed runs as history context so repeated
  tasks stay consistent with earlier decisions.

## Approval policy

A step requires approval when the planner flagged it, when its text matches a
dangerous-operation pattern, or when a declared tool is registered as high risk
or is missing from the plugin registry. `SMART_ROUTER_ORCHESTRATOR_APPROVAL_MODE`
selects the policy: `auto` (default), `always`, or `never`.
`SMART_ROUTER_ORCHESTRATOR_PLANNER_TIER` and
`SMART_ROUTER_ORCHESTRATOR_REVIEWER_TIER` choose the capability pools used for
the planner and reviewer passes.

## Operator console

- The Operations Center adopts the LocalLab console design language: the shared
  gradient palette, glass surfaces, gradient accents, and the LocalLab mark on
  the login screen and sidebar brand.
- New **Orchestrator** navigation entry in the Build group with a run table, a
  step timeline, an approval prompt, and a reviewer verdict panel.
- Documentation inside the console covers the orchestration flow alongside the
  existing page guide.

## Persistence

- New tables `v60_agent_runs` and `v60_agent_run_steps` in the existing
  control-plane database. The compatibility filename
  `control-v0.5.2.sqlite3` is unchanged; the in-place schema marker moves to
  `0.6.0`. No manual migration step is required.

## Security

Tool names in a plan remain declarative metadata. The router never executes
shell commands for a step, and the run record plus the audit log show the
intended tool only. Existing execution policy, approval, signing, identity, and
Docker/SSH separation remain the authoritative execution boundary.

## Acceptance

Automated planning, execution, approval, rejection, retry, history, persistence,
API permission, and console-surface tests pass with the full Smart Router suite.
The multi-agent flow is additionally covered by an end-to-end HTTP test through
the Operations Center API.
