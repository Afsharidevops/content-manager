# Hermes Smart Router v0.6.1 Release Notes

**Release date:** 2026-09-14

## Buffered clients and streaming upstreams

- A `/v1/chat/completions` request that omits `stream` is forwarded upstream
  with an explicit `stream: false`. The OpenAI contract treats the missing flag
  as "buffered", but a gateway may apply its own default and answer with
  `text/event-stream`; making the value explicit keeps the response buffered.
- When an upstream sends `text/event-stream` for a request that did not ask for
  streaming, the router collapses the deltas into a single `chat.completion`
  JSON body (content, tool-call fragments, model, usage, and finish reason) and
  returns it with `content-type: application/json`.
- Streaming clients are unchanged: `stream: true` still passes the upstream
  stream through untouched.

## Why it matters

Internal callers post to the router's own `/v1/chat/completions` endpoint. The
Orchestrator planner, executor, reviewer, and team synthesis decode that reply
as JSON, so a streamed body surfaced as
`agent returned no completion: data: {...}` and aborted the run. With this
release an orchestration plans and executes against a gateway that streams by
default.

## Upgrade

```bash
cd /path/to/content-manager
git pull --ff-only
sed -i 's/^SMART_ROUTER_IMAGE_TAG=.*/SMART_ROUTER_IMAGE_TAG=0.6.1/' .env
docker compose pull smart-router
docker compose up -d smart-router
curl -sS "http://$(grep '^SMART_ROUTER_BIND_IP=' .env | cut -d= -f2-):$(grep '^SMART_ROUTER_PORT=' .env | cut -d= -f2-)/health"
```

No database migration is involved: the control schema marker stays `0.6.0`.
