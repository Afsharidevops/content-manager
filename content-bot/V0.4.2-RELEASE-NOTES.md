# Content Bot v0.4.2 Release Notes

**Release date:** 2026-09-14

The Aparat uploader now matches the Aparat web uploader request, survives a
refused chunk, and can attach a thumbnail and a duration.

## Aparat uploader

- The final metadata call
  (`POST .../video/upload/upload/uploadId/<id>`) sends the body and the headers
  the Aparat uploader itself sends: `video_pass` as a number, `watermark` plus
  `watermark_bool`, `category`, `comment`, `kids_friendly`, `title`, `descr`,
  `tags` joined with `-`, `subtitle` as a list, `publish_date` as null, and the
  `isNext`, `jsonType`, `domain`, `currentUrl`, and `isRedesign` headers. The
  fields only the older body carried (`uploadId`, `upload_base_url`, `video`,
  and the empty playlist entries) are gone: the upload id already lives in the
  URL of the call.
- A chunk the upload server refuses (a `5xx`, `408`, `425`, or `429` answer, or
  a dropped connection) is uploaded again up to three times with a 1 s, 2 s,
  4 s backoff, and the `chunksdone` close of the upload is retried the same
  way. A `4xx` rejection is reported at once, and the last error text is the
  one the operator sees in the chat.
- `AparatClient.publish` takes the duration in seconds and a thumbnail image
  (raw bytes plus a filename, or a ready `data:image/...` URL) and passes both
  on. Without them Aparat picks a frame and reads the duration from the file.
  `platforms.video_meta` carries the duration of a generated clip, so a Media
  Studio video reaches Aparat with the seconds it was asked for.
- The client logs the upload start (file, size, chunk count), every chunk, a
  retried attempt, and the metadata answer, so `./manage.sh logs content` shows
  where an upload stopped. The session value itself is never logged.
- No new environment key: the retry count, the chunk size, and the timeout
  keep their documented defaults.

## Tests

`test_aparat.py` grew the retry, thumbnail, duration, header, and payload
cases. Content Bot suite: 434 tests.

## Upgrade

```bash
cd /path/to/content-manager
git pull --ff-only
sed -i 's/^CONTENT_BOT_IMAGE_TAG=.*/CONTENT_BOT_IMAGE_TAG=0.4.2/' .env
docker compose pull content-bot
docker compose up -d content-bot
./manage.sh content-aparat-check
```

A stored session and the existing `CONTENT_APARAT_*` keys keep working
unchanged.
