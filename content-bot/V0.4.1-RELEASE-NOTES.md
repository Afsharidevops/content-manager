# Content Bot v0.4.1 Release Notes

**Release date:** 2026-09-14

Aparat video publishing, on demand only, plus the media question on scheduled
proposals.

## Aparat publishing

- `content_bot/aparat.py` implements the Aparat upload flow end to end:
  reserve one slot (`upload_url`), send the file in chunks
  (`upload` -> `file/<uuid>` -> `chunksdone`), and submit the metadata with the
  final `uploadId` call. Tags are joined with `-` and kept between three and
  five names, and a `200` response that still carries an `errors` array is
  raised as a failure instead of being reported as a successful upload.
- Aparat issues no self-service upload key, so the adapter reuses the session
  of a signed-in browser: `CONTENT_APARAT_TOKEN` (the `jwt` value of
  `localStorage`) is preferred, `CONTENT_APARAT_COOKIE` (the whole `Cookie`
  header) is the fallback. `docs/APARAT-SETUP.md` walks through the copy step.
- `AparatChannel` refuses text, photo, and document posts with a readable
  message, and `send_video` accepts the per-platform `meta` (title,
  description, tags) that the other channels ignore.
- The platform is automatic, video-only, and on demand. The daily proposals
  and the scheduled routines never publish to Aparat on their own; the
  chooser marks the entry `Aparat (needs a video)` until a clip is attached,
  **All targets** skips it without one, and picking it without a video asks
  for the file, remembers the target on the draft, and uploads the clip as
  soon as it lands. An oversized clip that Telegram cannot hand to the bot
  (over 20 MB) fails with a message that names the limit and the Media Studio
  alternative instead of silently skipping the file.
- The publication row keeps the watch URL when Aparat returns one, and the
  chat confirmation carries the same link. A failed upload now also reports
  the reason in the chat, not only on the button.

## Scheduled proposals

- The media question now reaches scheduled proposals as well: when Media
  Studio is configured, every daily proposal asks text only, AI image, own
  image, or a video prompt, exactly like an on-demand draft.
- `media: ask` joins `media: auto` and `media: none` in
  `editorial-policy.yaml`, so each routine decides its own media mode.
- `pipeline.daily_enabled: false` turns the built-in daily pass off for
  deployments whose routines own the cadence. The default stays `true`.

## Configuration

New environment keys (all optional):

| Key | Default | Meaning |
| --- | --- | --- |
| `CONTENT_APARAT_TOKEN` | - | `jwt` value of a signed-in aparat.com tab |
| `CONTENT_APARAT_COOKIE` | - | Alternative `Cookie` request header |
| `CONTENT_APARAT_LABEL` | `Aparat` | Chooser label |
| `CONTENT_APARAT_CATEGORY` | `10` | Aparat category id |
| `CONTENT_APARAT_TAGS` | `technology,video,tutorial` | Fallback tags when the draft has fewer than three |
| `CONTENT_APARAT_WATERMARK` | `1` | `1` keeps the Aparat watermark, `0` turns it off |
| `CONTENT_APARAT_VIDEO_PASS` | `0` | `0` publishes, `1` keeps the upload private |
| `CONTENT_APARAT_API_BASE` | `https://www.aparat.com` | API host |
| `CONTENT_APARAT_TIMEOUT` | `120` | Per-request timeout (seconds) |
| `CONTENT_APARAT_CHUNK_BYTES` | `3145728` | Upload chunk size (bytes) |

## Tests

`test_aparat.py` (client, chunking, metadata, error mapping) and
`test_aparat_flow.py` (chooser, video request, pending target, publish on
arrival) join the suite, and the channel tests cover the per-platform `meta`
argument. Content Bot suite: 410 tests.

## Upgrade

```bash
cd /path/to/content-manager
git pull --ff-only
sed -i 's/^CONTENT_BOT_IMAGE_TAG=.*/CONTENT_BOT_IMAGE_TAG=0.4.1/' .env
docker compose pull content-bot
docker compose up -d content-bot
./manage.sh content-aparat-check
```

The state file is additive: `pending_target` and `media_wait_kind` are new
draft keys, and an older image ignores them. Aparat stays off until a session
is stored.
